# 5.50.0
Released 14th October 2026.

This is a maintenance release focused on crash prevention, data validation, and plugin API improvements.

**Plugin compatibility:** Existing plugins should continue to work unchanged, except for plugins relying on invalid or unsafe behavior.

## Fixes
- Invalid custom tile data on placed items no longer crashes the server.
- Out-of-range saved player hunger values are normalized when player data is loaded.
- Fireworks with an invalid flight-time multiplier are treated as invalid saved item data instead of crashing the server.
- Tiles saved outside world bounds, in the wrong chunk, or at an occupied tile position are discarded safely during chunk loading.
- Projectiles closed by plugins during projectile-hit callbacks stop processing the hit immediately.
- Explosion block and ignition lists now ignore blocks outside the affected world or its bounds.
- Failure to bind the dedicated Query UDP socket is reported as a warning and no longer aborts server startup.
- Block interactions now use the current block state after `PlayerInteractEvent`, avoiding calls on stale blocks when plugins replace them.
- System timezone auto-detection now runs when PHP reports `UTC` as its default timezone.
- Newly saved entities use Bedrock-format identifiers, while legacy entity IDs remain supported when loading existing worlds.
- Delayed chunk-population requests are retried each world tick, so external chunk locks cannot leave the generation queue stuck indefinitely.

## API
- `MeleeWeaponEnchantment` now provides `onPostAttackWithDamageEvent()`. The knockback enchantment uses the final plugin-adjusted `EntityDamageByEntityEvent` knockback value.
- `FarmlandHydrationChangeEvent` is now fired when dry farmland is about to revert to dirt. Plugins can cancel the event to preserve the farmland; a new hydration value of `-1` represents the dirt reversion.
